# 用户排查

适用于当前0.4系列和DSH0.2。安装与基本使用见 [中文README](../README.md) / [English](../README.en.md)。以下问题包含已确认的实现缺陷；修复状态统一以 [Backlog](backlog.md) 为准。

## 先检查这四件事

1. DSH版本满足 `>=0.2.0-rc.2 <0.3.0-0`，插件安装到实际正在使用的web profile。
2. 安装或修改宿主后已经重启DSH。插件patch在启动时读取。
3. 当前会话已选择模型，供应商未选择隐藏。新会话未选择模型时，状态行可以不显示。
4. 打开“设置→用量状态”，查看供应商、解析数据源、凭据来源和错误消息。

DSH0.1使用历史版本0.3.2；它不适配0.2。0.4.0存在RPC挂载缺陷，应升级至最新兼容版，不要停在0.4.0。

## 没有读数或状态异常

| 症状 | 检查与处理 |
|---|---|
| 设置页/整行都没有出现 | 确认profile、重启、插件未在启动恢复中被禁用；开发安装确认预构建文件存在 |
| 一直“读取中”或报remote挂载失败 | 查客户端控制台/宿主日志；入口出现不代表RPC贡献已挂载。维护者按 [发布验收](release.md) 核对真实registry |
| “未配置”，但DSH中已有key | 确認数据源和ref；普通自定义provider id的端点自动识别目前未完整传到客户端，见 [A08](backlog.md#a08)；可显式选择数据源 |
| 自建源提示缺接口地址 | 高级区填写所用实例地址；不会为Sub2API猜一个默认站点 |
| “密钥无效” | 检查key所属产品/区域。z.ai国内与国际key不通用；OpenCode Go需要对应订阅或权限 |
| 环境key输入框不可编辑 | 环境值优先于存储值；修改启动DSH的环境并重启。UI锁定提示仍有不完整路径，见 [A16](backlog.md#a16) |
| 旧值+⚠ | 最近一次源请求失败。设置页可查看源失败详情；旧值悬停暂不总能显示具体原因，见 [A10](backlog.md#a10) |
| 断线后仍显示正常旧值 | 成功后的RPC失败目前未完整标陈旧，见A10；先恢复连接/重启，并核对设置页错误和时间 |

`env (direct)`/`file (direct)` 表示插件用了直接读取兜底，不表示密钥上传到了浏览器。凭据位置是DSH home下的凭据文件，不一定是默认 `~/.dsh`。请勿在issue中粘贴该文件内容或完整日志里的密钥/token。

## 当前版本需要注意的操作

| 操作或结果 | 当前限制 |
|---|---|
| 高级区指定凭据名 | provider级ref未进入请求链路，见 [A01](backlog.md#a01)。不要据此认为已切换账户；修复前使用DSH供应商原本声明的凭据策略并核对来源 |
| 固定z.ai端点 | 显式端点pin在装配中丢失，失败时仍可能试镜像，见 [A03](backlog.md#a03) |
| 改端点/凭据后立即看到旧数字 | 缓存/在途未按配置身份隔离，见 [A04](backlog.md#a04)；核对来源，必要时重启后重新读取 |
| 旧配置迁移后选择隐藏 | legacy models可能仍产生后台请求，见 [A05](backlog.md#a05)；维护者应检查迁移文档，用户可停用插件 |
| 零配置供应商↑↓无反应 | 默认order未包含自动发现项，见 [A09](backlog.md#a09) |
| 改空闲刷新分钟数后频率不变 | 定时器未重调，浏览器轮询另会触发查询，见 [A06](backlog.md#a06)；不要将配置值当作实时网络频率保证 |
| Moonshot余额≥100元却很小 | 当前会错误除以100，见 [A02](backlog.md#a02)。以 [官方控制台/接口](https://platform.kimi.com/docs/api/balance.md) 的人民币元值为准 |
| DeepSeek突然显示0 | 真实0可能合法，但非法/缺失金额也会被当前解析器当0，见 [A07](backlog.md#a07)。单凭该显示不能判定账户余额耗尽 |

Kimi Code和Sub2API尚缺真实账户验证；高阈值颜色、密钥手写后生效和OpenCode非零路径的验证状态也在Backlog记录。

## 恢复与报告问题

停用或卸载前确认使用的是目标profile：

```bash
dsh plugin --profile web remove dsh-usage-state
```

重启DSH使patch变化生效。需要使用其他profile时换成实际名称。

[提交issue](https://github.com/takboo/dsh-usage-state/issues)时提供：插件/DSH版本、安装来源、provider id、所选模式、是否自定义端点、脱敏错误和复现步骤。不要提交密钥值、完整凭据文件、会话内容或带登录token的URL；截图可只保留用量状态区域。
