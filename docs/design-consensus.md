# 设计共识

本文件记录当前有效的设计约定，不表示所有约定已完整实现。代码位置和实际数据流见 [架构](architecture.md)，偏差与验收标准见 [Backlog](backlog.md)，决策变化的理由见 [设计修订](design-changelog.md)。领域定义以 [术语表](../CONTEXT.md) 为准。

## 1. 目标与范围

在当前模型的供应商路由对应的账户上，读取余额或套餐额度，并在输入框上方显示。配置单元为provider，模型清单仅供参考；读数属于账户，不用于归因单个模型、会话或回合的成本。

不做成本统计、模型价格目录、预算、历史账单、按回合采样、原生统计行替换，也不往会话日志写入自有事件。完整否决项在 [Backlog](backlog.md#non-goals)。新增需求不得仅因已有接口就顺手扩展范围。

## 2. 数据源和账户身份

数据源负责描述端点、模式、凭据候选及返回字段语义。当前五家来源与语义集中在 [适配器指南](adapters.md)，此处不重复接口矩阵。

provider是模型路由，source是读数来源，account是余额/额度所属身份。当前实现按source+mode合并目标，适用于不同路由确实共享同一账户的情况；不同key/实例不能仅据此认定同账户。当前版本没有独立多账户身份模型，重新配置后的缓存隔离仍待 [A04](backlog.md#a04) 完成。

## 3. 配置与发现

- provider默认“自动”；按已知路由名或声明的端点建议数据源，再选择该源主模式。该建议不保证识别所有自定义名称，客户端端点信息缺口见 [A08](backlog.md#a08)。
- 可选“自动 / API / Coding Plan / 隐藏”，模式选项按数据源能力过滤。隐藏不应继续产生目标；旧配置路径的偏差见 [A05](backlog.md#a05)。
- 自建源需要用户填写实例地址。显式端点应优先于provider声明端点，再优先于source默认；显式固定地址应禁止镜像，当前装配缺陷见 [A03](backlog.md#a03)。
- 上下按钮调整供应商顺序；默认配置排序缺陷见 [A09](backlog.md#a09)。
- 配置由DSH保存，命名空间与插件profile条目id均为usage-state。旧models字段用于迁移，不应成为绕过新版provider选择的长期平行配置。

## 4. 凭据和隐私

有效凭据应体现用户选择：显式覆盖、该provider的凭据声明、source内置ref。平台凭据服务负责解析ref和保存密钥；无法读取时的直接兜底要明确标来源。provider级覆盖未进入请求的缺陷由 [A01](backlog.md#a01) 跟踪。

宿主不通过插件RPC返回已保存的密钥值。用户主动粘贴的草稿经过平台凭据服务写入所用home；插件不另建明文凭据文件。环境变量优先且通常只读。写入结果、只读状态和失败原因应如实反馈，现有交互缺口见 [A16](backlog.md#a16)。

插件只查询账户读数，读取显示所需模型/供应商信息；不写会话日志，不上报读数。测试与问题报告不包含真实key。

## 5. 展示与降级

唯一挂载点是conversation.input.dock，位于输入卡片上方；保留原生统计行和上下文计量器。状态行跟随当前模型选择，不复制到历史回合。没有选中模型、槽位未开放或provider隐藏时，可以不显示。

余额带币种；套餐百分比为已用。额度窗口由实际数据源决定，可包括5h/1d/7d/30d，不在展示层假定所有套餐都有相同窗口。SVG环表达已用百分比，默认≥80%琥珀、≥95%红；颜色和进度环可配置，沿用progressBar配置键以兼容旧文档。

数值应可信：非法字段不冒充真实0；失败保留上次成功值，同时标记年龄和错误，首次失败只显示原因。源失败与RPC传输失败应可区分。实际偏差包括 [A02](backlog.md#a02)、[A07](backlog.md#a07)、[A10](backlog.md#a10)，不能用“绝不造0”描述尚未满足约定的当前实现。

悬浮提示承载来源、模式、余额构成、重置时刻和失败细节；点击状态行打开设置尚未实现。中英文案由客户端词典提供并跟随DSH语言。

## 6. 刷新

默认策略：回合结束后延迟2s，宿主有5min兜底，成功请求默认最小间隔60s；同一有效身份的在途请求去重，force可绕过成功间隔，失败可立即重试。

当前浏览器30s轮询getState，而该方法触发源refresh；因此实际空闲请求通常受60s最小间隔控制。编辑intervalMinutes未重调宿主timer。调度语义和配置生效的修复见 [A06](backlog.md#a06)，此处不宣称前端没有定时拉取。

## 7. 传输和分发

配置通过DSH configForms/volatile配置传输；读数通过Typert，方法面为getState(force)与describeCredentials()。客户端挂载贡献和宿主激活是两条独立契约，不能只凭入口出现判断成功。

宿主有zod v4清单；客户端贡献不携带zod并提供所需codec工厂。客户端使用平台模块表，宿主共享schema依赖按平台约定声明。细节见架构与 [平台说明](platform-notes.md)。

npm包与仓库保留预构建产物，正式发版验证tarball。GitHub浮动分支与npm版本不保证恒同；支持范围以包的engines.dsh及相关peer声明为准，新增平台发布线先验再改声明。发布步骤见 [发布与验收](release.md)。

## 8. 验证和文档

验证分别记录源码检查、最终产物契约、干净安装、真实账户和视觉覆盖。测试全绿不等于所有使用路径正确；历史真机证据不代表对本次修改进行了新验收。

当前文档职责见 [导航](index.md)。Backlog是唯一未完成事项状态来源；历史审计和修订保留基线，不随实现进度重写。设计改变追加修订，文档纠错不自动扩大产品范围或宣称代码已修。
