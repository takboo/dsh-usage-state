# 设计共识

本文件记录当前有效的设计约定，不表示所有约定已完整实现。代码位置和实际数据流见 [架构](architecture.md)，偏差与验收标准见 [Backlog](backlog.md)，决策变化的理由见 [设计修订](design-changelog.md)。领域定义以 [术语表](../CONTEXT.md) 为准。

## 1. 目标与范围

在当前模型的供应商路由对应的账户上，读取余额或套餐额度，并在输入框上方显示。配置单元为provider，模型清单仅供参考；读数属于账户，不用于归因单个模型、会话或回合的成本。

不做成本统计、模型价格目录、预算、历史账单、按回合采样、原生统计行替换，也不往会话日志写入自有事件。完整否决项在 [Backlog](backlog.md#non-goals)。新增需求不得仅因已有接口就顺手扩展范围。

## 2. 数据源和账户身份

数据源负责描述端点、模式、凭据候选及返回字段语义。当前五家来源与语义集中在 [适配器指南](adapters.md)，此处不重复接口矩阵。

provider是模型路由，source是读数来源，account是余额/额度所属身份。当前仍按source+mode选择一个目标，适用于不同路由确实共享账户的情况；不同key/实例不能据此认定同账户。Unreleased已按有效目标签名、私有凭据摘要和generation隔离重新配置后的旧值/旧请求，见 [A04](backlog.md#a04)，但没有新增独立多账户支持。本文当前行为以本地整改为准，npm0.4.4尚不包含这些修复。

## 3. 配置与发现

- provider默认“自动”，按路由名或声明端点建议来源并选主模式；origin-only endpointHints经RPC传到两UI，不保证识别所有未知来源。
- “自动 / API / Coding Plan / 隐藏”按来源能力提供；隐藏或权威空目录不产生目标，未知目录才保留配置降级。上下按钮按当前可见顺序调整，包括零配置项。
- 有效端点/ref优先级由共享解析集中决定：显式provider覆盖→legacy source默认→provider声明origin/来源默认。显式端点pin保留到读取层，不尝试镜像。
- 配置由DSH保存，命名空间和profile条目id均为usage-state。旧models只经normalize迁移，不作平行优先轮询路径。

## 4. 凭据和隐私

凭据覆盖作为首选，之后探测DSH声明及source内置ref；请求和describeCredentials共用有效目标与候选顺序。保存优先写显式ref，平台凭据服务负责解析/持久化，直接兜底明确标来源。配置只读与key权限分别判断。

宿主不返回已保存key值，也不传私有身份摘要；endpointHints只含origin。已解析请求key的原文回显在快照错误边界精确替换，避免detail经RPC泄露本次凭据。用户主动粘贴草稿经平台服务写入所用home，插件不另建明文文件。环境值通常只读。

配置写入布尔false和rejection可见；key保存/清除处理错误及busy/pending，成功后清旧身份、刷新描述和读数。插件不写会话日志、不上报读数；测试使用fake key。

## 5. 展示与降级

唯一挂载点是conversation.input.dock，位于输入卡片上方；保留原生统计和上下文计量器。跟随当前模型，不复制到历史回合；没有模型、槽位未开放或隐藏时可不显示。

余额带币种并按来源单位解析，Moonshot以元计；非法DeepSeek金额跳过，无有效读数时报parse，不冒充真实0。窗口来自来源，可能是5h/1d/7d/30d；百分比表示已用。SVG环与80%/95%阈值可配置，沿用progressBar键。

同一有效身份失败保留旧值并显示年龄/原因；源失败和RPC断线均可见。配置/凭据身份变更清旧值，generation拒绝旧RPC复原；普通在途RPC后的显式force排一次，已有force则共享。

悬浮提示显示来源、模式、余额构成、重置时刻和失败细节；点击打开设置未实现。中英文案跟随DSH语言。真实账户/视觉范围仍见Backlog。

## 6. 刷新

默认回合结束2s后调度刷新、宿主5min兜底、成功请求60s最小间隔；同有效身份在途去重，force可绕过成功间隔，主动失败重试不受成功节流限制。

浏览器30s轮询getState(false)，仅初始化缺失/变更身份，其余读取镜像，不缩短idle频率。修改intervalMinutes重调timer。目标/凭据代次检查使ABA、晚lookup/HTTP不能写回旧值；移除和stop不衍生新请求，ctx.effect负责调度清理。

## 7. 传输和分发

配置通过DSH configForms/volatile配置传输；读数通过Typert，方法面为getState(force)与describeCredentials()。客户端挂载贡献和宿主激活是两条独立契约，不能只凭入口出现判断成功。

宿主有zod v4清单；客户端贡献不携带zod并提供所需codec工厂。客户端使用平台模块表，宿主共享schema依赖按平台约定声明。细节见架构与 [平台说明](platform-notes.md)。

npm包与仓库保留预构建产物，正式发版验证tarball。GitHub浮动分支与npm版本不保证恒同；支持范围以包的engines.dsh及相关peer声明为准，新增平台发布线先验再改声明。发布步骤见 [发布与验收](release.md)。

## 8. 验证和文档

验证分别记录源码检查、最终产物契约、干净安装、真实账户和视觉覆盖。测试全绿不等于所有使用路径正确；历史真机证据不代表对本次修改进行了新验收。
